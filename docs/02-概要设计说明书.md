## 1. 系统总体架构

### 1.1 架构风格

采用 **前后端分离 + 跨语言算法引擎** 的混合架构：

- **表现层**：Vue 3 单页应用（SPA）
- **业务层**：Spring Boot 单体后端（REST API）
- **算法层**：Python 算法引擎（独立进程，命令行契约通信）
- **数据层**：MySQL（业务数据） + Redis（缓存） + 文件系统（数据集/图表/模型）

### 1.3 跨语言调用设计

Java 后端通过 `ProcessBuilder` 启动 Python 进程，采用**单行 JSON 契约**：

- **请求**：命令行参数（`--algo` / `--model` / `--user` / `--movie` / `--top` 等）
- **响应**：stdout 最后一行非空 JSON（stdout/stderr 合并，容忍第三方库告警）
- **错误**：非 0 退出码 + `{"error": "...", "trace": "..."}`
- **编码**：强制 UTF-8（`reconfigure(encoding="utf-8")`）

> 设计要点：算法层**完全解耦**——同一脚本既可被后端调用，也可命令行独立运行（便于教师演示与调试）。

## 5. 接口设计

### 5.1 接口规范

- 统一前缀：`/api/admin/**`（管理端）
- 统一响应体：`RestResponse<T> { code, message, response }`（`code=1` 成功，非 1 失败）
- 认证：请求头携带 Token，由拦截器校验

### 5.2 核心接口清单

| 模块 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 认证 | POST | `/api/admin/login` | 登录 |
| 总览 | POST | `/api/admin/dashboard/...` | 指标卡片 + 趋势 |
| 动漫 | POST | `/api/admin/video/page/list` | 分页查询 |
| 动漫 | POST | `/api/admin/video/select/{id}` | 详情（真实数据） |
| 动漫 | POST | `/api/admin/video/getVideoDetailByVideoId/{id}` | 编辑页数据（含标签） |
| 动漫 | POST | `/api/admin/video/userAnalysis/{id}` | 相似动漫 |
| 分析 | POST | `/api/admin/video/analysis/videoAttr` | 动漫属性统计 |
| 分析 | POST | `/api/admin/video/analysis/userAttr` | 用户属性统计 |
| 预测 | POST | `/api/admin/predict` | 热度预测（转发 Python） |
| 推荐 | POST | `/api/admin/recommend` | 智能推荐（转发 Python） |
| 收藏 | POST | `/api/admin/collection/toggle` | 追番/取消 |
| 收藏 | POST | `/api/admin/collection/list` | 我的追番 |
| EDA | GET | `/eda/**` | EDA 图表静态资源 |

### 5.3 算法引擎契约

**推荐（`recommend_api.py`）**

```
入参：--algo <算法> [--user <int>] [--movie <标题>] [--keywords <词>] [--top <int>]
出参：{"algo":"...", "movies":[{"title":"...","movieId":<int>,"score":<float|null>}, ...]}
```

**预测（`predict_api.py`）**

```
入参：--model <模型> --budget <集数> --popularity <成员数> --runtime <时长> --language <语言> --status <类型>
出参：{"model":"...", "prediction":<float>, "metrics":{"rmse":..,"mae":..,"r2":..}, "trained_now":<bool>}
```

## 6. 关键流程设计

### 6.1 热度预测流程

```
前端表单 → PredictController → ProcessBuilder 调用 predict_api.py
   → 检查 model_cache/predict_<model>.joblib
        ├─ 存在 → 加载模型 → 预测
        └─ 不存在 → 读取 data/train.csv → 特征工程 → 训练 → 评估 → 缓存 → 预测
   → 返回 JSON → 前端展示预测值 + R²/RMSE/MAE + 热度等级
```

### 6.2 推荐流程

```
前端选择算法 → RecommendController → 校验(Redis查缓存)
   → ProcessBuilder 调用 recommend_api.py --algo ...
   → 算法模块（naive / personal / ensemble / deep）
   → ID 映射回 movieId/tmdbId → enrich（补海报/评分/热度）
   → 写 Redis（TTL 1h） → 返回前端卡片墙
```

### 6.3 部署设计

## 7. 设计约束与权衡

| 约束 | 权衡决策 |
| --- | --- |
| Python 首次调用慢（模型训练） | 采用**模型缓存 + Redis 缓存**，首次训练后秒级返回 |
| 跨语言通信开销 | 采用命令行进程（简单可靠），牺牲少量性能换取解耦 |
| 评分矩阵稀疏（98.9%） | 引入 SVD 与 NCF 缓解，KNN 作为基线对比 |
| 热度长尾分布 | 采用 log1p 变换 + 树模型 |
| 本地部署无 GPU | 深度学习采用 CPU 版 PyTorch，控制模型规模 |
