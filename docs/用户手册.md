## 1. 系统概述

### 1.1 系统简介

番析 AniScope 是一套面向动漫数据分析与推荐场景的后台管理系统。系统以 MyAnimeList
公开数据集为数据底座，内置数据清洗、可视化分析、热度预测、个性化推荐与在线模型训练
五类能力，并以统一的 Web 后台向使用者提供操作入口。

与普通的数据展示页面不同，本系统把"**分析结论**"与"**可运营的业务功能**"放在同一套
后台里：使用者既能看到全库 24661 部动漫的题材、评分、热度分布等统计结果，也能在同
一界面完成数据集上传、模型训练评估、用户与动漫信息维护等工作。

### 1.2 功能模块总览

| 模块 | 入口 | 核心能力 |
| :--- | :--- | :--- |
| 首页看板 | 主页 | 核心指标卡、活跃度与播放量趋势、发行年份分布、类型占比、热度 TOP10 |
| 动漫库 | 数据与模型 | 24661 部动漫检索、详情、增删改、播放 |
| 用户管理 | 用户与运营 | 用户注册与登录、资料维护、启用禁用、密码重置 |
| 我的追番 | 用户与运营 | 收藏清单、评分记录、观看历史 |
| 数据分析 | 数据分析 | 用户属性分析、动漫属性分析、EDA 图表库、态势感知大屏 |
| 智能推荐 | 算法服务 | 基于人口统计属性的推荐、基于内容相似度的推荐 |
| 热度预测 | 算法服务 | 6 种回归模型预测动漫热度，输出 RMSE / MAE / R² |
| 模型管理 | 数据与模型 | 数据集上传与管理、模型在线训练与评估、任务状态跟踪 |
| 态势感知大屏 | 可视化大屏 | 1920×1080 等比缩放、实时时钟、30 秒自动刷新、动态热度榜单 |

### 1.3 系统架构（使用者视角）

```
浏览器（Vue 3 + Element Plus + ECharts）
        │  HTTP / JSON（统一返回 {code, message, response}）
        ▼
后端服务（Spring Boot，端口 8000，内嵌托管前端页面）
        │  ProcessBuilder 调用
        ▼
算法引擎（Python：scikit-learn / LightGBM / PyTorch）
        │
        ▼
数据层（MySQL 8 业务库 + Redis 会话 + CSV 数据集文件）
```

使用者无需关心内部实现，只需知道：**页面上的每个数字和图表都来自后端接口，接口再从
数据库和算法引擎取数**。当某个图表为空时，通常是数据层没有对应记录，可在第 6 章找到
对应处理方法。

## 3. 快速开始

### 3.1 启动后端

1. 将项目文件夹放到本地任意路径（建议纯英文路径，避免中文与空格）
2. 确认 MySQL 与 Redis 服务已安装并已启动（Windows 服务名通常为 `MySQL80` 与 `Redis`）
3. 打开命令提示符，进入项目的 `backend` 目录后启动：

```bat
cd anime-system\backend
mvn -Dmaven.test.skip=true compile spring-boot:run
```

4. 看到 `Started MediaApplication` 字样即表示启动成功，浏览器访问
   <http://localhost:8000/admin> 即可。

> **首次启动提示**：第一次运行需要编译，约需 30~90 秒，请勿关闭窗口。

> **重复启动提示**：如果之前的后端进程还占着 8000 端口，请先结束该进程，
> 否则会出现两个进程同时编译、导致后端启动失败的情况。

> **只跑后端即可**：前端页面由后端一并托管（`/admin`），日常使用不需要额外启动前端。

### 3.2 前端开发模式（可选）

只有修改前端源码做开发调试时，才需要另开一个终端运行 Vite 开发服务器
（端口 8002，已把 `/api` 代理到 8000）：

```bat
cd anime-system\frontend
npm run dev
```

修改前端后重新构建，让后端托管新产物：

```bat
cd anime-system\frontend
npm run build
xcopy /E /I /Y /Q admin\* ..\backend\src\main\resources\static\admin\
```

然后重启后端即可生效。

### 3.3 手动部署（无脚本环境）

**第一步：初始化数据库**

```bat
mysql -uroot -p123456 < sql\anime_mangage_db.sql
mysql -uroot -p123456 < sql\dataset_model_schema.sql
mysql -uroot -p123456 < sql\optimize_schema.sql
```

**第二步：导入业务数据**

```bat
.venv\Scripts\python.exe sql\import_data.py --password 123456
.venv\Scripts\python.exe scripts\data_prep\build_full_dataset.py --password 123456
```

**第三步：刷新用户行为数据**

看板的播放量与活跃度趋势依赖行为数据表，需执行一次把时间轴对齐到最近 30 天：

```bat
.venv\Scripts\python.exe scripts\data_prep\refresh_activity_data.py
```

**第四步：启动后端**

```bat
cd backend
mvn -Dmaven.test.skip=true compile spring-boot:run
```

**第五步：访问系统**

浏览器打开 <http://localhost:8000/admin>，使用 `admin / 123456` 登录。

### 3.4 首次登录

在登录页输入账号 `admin`、密码 `123456` 点击「登录」。系统会校验登录态并跳转到首页
看板。登录态保存在浏览器 Cookie 中，有效期 30 天，关闭浏览器后再次访问无需重新登录。

> 提示：若直接访问 `/#/dashboard` 而未登录，系统会自动拦截并跳转到登录页，登录成功后
> 自动返回原本要访问的页面。

### 4.2 动漫库管理

> **入口**：侧边栏 → 数据与模型 → 动漫库

系统内置 24661 部动漫的完整信息，支持分页浏览、条件检索与增删改。

**图 4-3 动漫库列表**

> 截图占位：动漫列表页，含顶部检索条件与分页控件。`images/video-list.png`

**检索与浏览**

1. 在列表上方选择检索条件（按名称、国家、类型、动画类型等），输入关键字后点击「查询」
2. 列表按热度分降序排列，底部翻页浏览
3. 点击任意一行进入**详情页**，可查看完整属性（制作公司、原作来源、首播季度、片长、
   评分、成员数等）并在线播放

**新增动漫**

1. 点击右上角「新增」按钮
2. 填写名称、评分、成员数、片长、类型等字段，带红色星号的为必填项
3. 点击「确定」提交，成功后返回列表并提示操作结果

**编辑与删除**

- **编辑**：在列表行操作列点击「编辑」，修改后保存，列表即时刷新
- **删除**：点击「删除」，系统弹出二次确认框，确认后该条记录被移除

> 提示：删除操作不可撤销，若误删可重新导入数据。

### 4.3 用户管理

> **入口**：侧边栏 → 用户与运营 → 用户列表 / 管理员管理

**图 4-4 用户管理列表**

> 截图占位：用户列表，含头像、用户名、角色、状态、注册时间。`images/user-list.png`

**用户列表**

支持按用户名、真实姓名、角色、状态筛选，列表展示用户基础信息与最近登录时间。

**新增用户**

1. 点击「新增」，填写用户名、密码、真实姓名、手机号、角色等信息
2. 用户名须以字母开头，仅可包含字母、数字与下划线，长度 3~20 位
3. 密码长度 6~32 位，系统自动以 BCrypt 加密后存储
4. 保存后系统会写入一条用户行为日志

在操作列点击「启用 / 禁用」可切换账号状态。禁用后该用户无法登录，已有登录态在下一次

点击「删除」并二次确认。系统采用**逻辑删除**（标记 deleted=1），记录仍保留在数据库中
以维持与其它表的关联关系，因此删除后不会再出现在用户列表中。

**管理员管理**

用于维护具备后台操作权限的账号，字段与用户列表一致。

**个人资料**

侧边栏右上角头像 →「个人中心」，可修改昵称、邮箱、头像与密码。

### 4.8 模型管理

> **入口**：侧边栏 → 数据与模型 → 数据集管理 / 在线训练与评估

这是本系统面向算法工程师的核心模块，实现"上传数据 → 训练模型 → 查看指标"的完整闭环。

#### 4.8.1 数据集管理

**图 4-11 数据集管理**

> 截图占位：数据集列表，含名称、文件大小、行数、上传人、创建时间。`images/dataset.png`

| 操作 | 说明 |
| :--- | :--- |
| 上传 | 支持 `.csv` 格式，系统自动统计行数与列名；单文件上限 1024 MB |
| 查看详情 | 弹窗展示行数、列名清单、文件大小与上传备注 |
| 改名 | 修改数据集名称与备注 |
| 删除 | 二次确认后删除记录，同时清理磁盘上的文件副本 |

> 提示：上传时若选择非 CSV 文件，系统会提示「仅支持 .csv 数据集文件」并拒绝上传；
> 若文件名包含路径符号，系统会判定为非法文件名以阻断目录穿越。

#### 4.8.2 在线训练与评估

**图 4-12 在线训练与评估**

> 截图占位：训练页面，含算法下拉、数据集下拉、进度条与指标区。`images/model-train.png`

操作步骤：

1. 在「算法」下拉框中选择一种算法，系统支持 6 种：
   `lr`（线性回归）、`knn`（K 近邻）、`svm`（支持向量回归）、`dt`（决策树）、
   `rf`（随机森林）、`lgbm`（LightGBM）
2. 在「数据集」下拉框中选择已上传的数据集
3. 按需勾选「仅评估」——只计算指标不重新训练，适合评估已有模型
4. 点击「开始训练」，页面每 2 秒轮询一次任务状态，进度条实时推进
5. 训练完成后自动展开指标区，显示 **RMSE**（均方根误差）、**MAE**（平均绝对误差）、
   **R²**（决定系数）、训练耗时与任务追踪号

指标含义：

| 指标 | 含义 | 越好 |
| :--- | :--- | :--- |
| RMSE | 预测值与真实值的均方根误差，越小越准 | 越小越好 |
| MAE | 预测值与真实值的平均绝对误差 | 越小越好 |
| R² | 模型对数据变化的解释比例，取值 0~1 | 越接近 1 越好 |

下方任务列表保留全部历史训练记录，含算法、数据集、状态、进度、耗时与追踪号。

> 提示：训练在独立线程池中执行，不会阻塞页面其它操作。状态流转为
> 排队中（PENDING）→ 执行中（RUNNING）→ 训练成功（SUCCESS）或训练失败（FAILED）。

| 右列 | 题材热度 TOP10 横向条形图、用户评分档位玫瑰图、原始语言分布环形图 |
| 底栏 | 数据源说明、自动刷新开关与倒计时进度、最后更新时间 |

交互说明：

- **自动刷新**：默认开启，每 30 秒拉取一次最新数据，底栏显示倒计时秒数与进度条；
  关闭开关后不再自动刷新
- **手动刷新**：点击顶栏「刷新」立即取数
- **全屏**：点击顶栏「全屏」进入投屏模式，再点一次退出
- **异常提示**：接口调用失败时顶栏指示灯变为红色并显示「数据链路异常」，页面保留
  上一次的数据不做清空

## 5. 典型操作流程

### 流程一：系统启动与数据总览

1. 在 `backend` 目录执行 `mvn -Dmaven.test.skip=true compile spring-boot:run`，等待控制台出现「Started MediaApplication」
2. 浏览器自动打开首页看板，确认四张指标卡有数（动漫库总量应为 24661）
3. 观察趋势图：若曲线只有左侧一小段或指标为 0，说明行为数据时间轴未对齐，执行
   `.venv\Scripts\python.exe scripts\data_prep\refresh_activity_data.py` 后刷新页面
4. 点击侧边栏「可视化感知大屏」，按 F11 或点击「全屏」进入投屏演示

### 流程二：上传数据集并训练一个模型

1. 进入「数据与模型 → 数据集管理」，点击「上传」
2. 选择准备好的 `.csv` 文件（建议首行为列名），填写数据集名称与备注，点击确定
3. 上传成功后列表新增一条记录，行数与列名会自动统计
4. 进入「数据与模型 → 在线训练与评估」
5. 选择算法 `rf`（随机森林）与刚上传的数据集，点击「开始训练」
6. 观察进度条推进，训练完成后查看 RMSE、MAE、R² 三个指标
7. 记下任务追踪号（traceId），若结果异常可在 `_boot.log` 中按该编号定位完整日志

### 流程三：动漫信息维护

1. 进入「数据与模型 → 动漫库」，在检索框输入关键字，点击「查询」
2. 点击目标动漫进入详情页，查看属性与播放效果
3. 返回列表，点击「编辑」修改名称或属性，保存后列表即时更新
4. 确认不再需要该记录时点击「删除」，在确认框中再次确认

### 流程四：为动漫评分与收藏

1. 进入「动漫库」，找到目标作品进入详情页
2. 在详情页设置评分（1~10 分）并点击「收藏」
3. 进入「用户与运营 → 我的追番」，即可看到刚才的评分与收藏记录
4. 在「用户属性分析」中，新的评分与行为会体现在用户特征里

### 流程五：获取推荐与热度预测

1. 进入「算法服务 → 用户属性推荐」，选择目标用户后点击「推荐」，查看 Top10 结果
2. 进入「算法服务 → 动漫属性推荐」，选择目标动漫后点击「推荐」，查看相似作品
3. 进入「算法服务 → 热度预测」，填写预算、片长、语言等特征，选择模型后点击「预测」
4. 记录预测值与该模型的 R²，作为选型参考

## 6. 常见问题解答

**Q1：启动后端时窗口一闪而过，或命令执行后没有任何输出？**

A：多为 Windows 执行策略或杀毒软件拦截。右键脚本 → 属性 → 勾选「解除锁定」→ 应用；
请在命令行中直接执行 `mvn -Dmaven.test.skip=true compile spring-boot:run` 查看完整报错信息。

**Q2：后端启动时提示 `ClassFormatError: Invalid method Code length 0`？**

A：这是编译产物被写坏，通常由**两个 Maven 进程同时编译**引起（例如 IDEA 里和脚本里各
跑了一个后端）。关闭 IDEA 中的后端运行，重新执行启动命令即可；
残留进程清理。

**Q3：页面能打开，但所有图表都是空的 / 指标全是 0？**

A：数据库尚未导入业务数据，或行为数据时间戳过旧。按 3.3 节补跑 `import_data.py`、
`build_full_dataset.py` 与 `refresh_activity_data.py`。

**Q4：提示「用户未登录」或自动跳回登录页？**

A：登录态 Cookie 失效（超过 30 天）或服务器重启导致会话丢失，重新登录即可。登录
成功后会自动跳回原本要访问的页面。

**Q5：上传数据集时提示「仅支持 .csv 数据集文件」？**

A：系统只接受 `.csv` 扩展名的文件。请确认文件确实是 CSV 且后缀正确。

**Q6：训练任务一直停在「排队中」？**

A：检查 Python 虚拟环境是否可用（`.venv\Scripts\python.exe`），以及
`algorithm/prediction/train_eval_api.py` 是否存在。首次调用 Python 引擎会稍慢。

**Q7：训练报错提示找不到 torch / lightgbm？**

A：算法依赖未安装。执行 `.venv\Scripts\pip.exe install -r requirements.txt`；如需
CPU 版 PyTorch，用 `pip install torch --index-url https://download.pytorch.org/whl/cpu`。

**Q8：端口 8000 被占用导致启动失败？**

A：在任务管理器中结束占用该端口的进程，或执行 `netstat -ano | findstr :8000` 找到 PID 后 `taskkill /PID <PID> /F`。

**Q9：态势感知大屏显示不全或被裁切？**

A：大屏按 1920×1080 等比缩放，不会变形。若内容偏小请放大浏览器窗口或按 F11 全屏。

**Q10：修改了前端代码但页面没变化？**

A：生产模式下页面由后端托管，需要重新构建并复制产物：

```
cd frontend
npm run build
xcopy /E /I /Y /Q admin\* ..\backend\src\main\resources\static\admin\
```

然后重启后端。或直接用 `npm run dev` 启动开发模式获得热更新。

### 7.3 术语表

| 术语 | 含义 |
| :--- | :--- |
| 热度分（heat score） | 综合评分、成员数、收藏数等指标加权得到的作品热度值 |
| RMSE | 均方根误差，衡量预测值与真实值的整体偏差 |
| MAE | 平均绝对误差，衡量预测偏差的绝对值水平 |
| R² | 决定系数，衡量模型解释数据变化的能力，越接近 1 越好 |
| traceId | 请求追踪号，贯穿一次请求的前后端日志，用于排查问题 |
| EDA | 探索性数据分析（Exploratory Data Analysis） |
