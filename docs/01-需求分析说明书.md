## 1. 项目背景与目标

### 1.1 背景

动漫产业数据规模庞大、维度丰富（评分、成员数、收藏数、题材、制作公司、开播时间等），
且用户行为数据具有典型的**高稀疏、长尾分布**特征。如何从海量元数据与用户行为中
挖掘规律、预测热度、生成个性化推荐，是数据分析与推荐系统领域的经典问题。

本项目以真实动漫数据集为对象，构建一套覆盖
「**数据采集 → 数据清洗 → 探索性分析 → 特征工程 → 算法建模 → Web 可视化**」
全流程的动漫数据分析与推荐平台。

### 1.2 建设目标

| 编号 | 目标 | 可验证标准 |
| --- | --- | --- |
| G1 | 完成动漫元数据与评分数据的接入、清洗与整合 | 产出标准化数据集，字段完整率 ≥ 99% |
| G2 | 完成多维探索性数据分析（EDA）并可视化 | 输出 ≥ 20 张中文分析图表 |
| G3 | 实现动漫热度预测算法层 | ≥ 6 种机器学习/深度学习模型，R² ≥ 0.5 |
| G4 | 实现个性化推荐算法层 | ≥ 9 种推荐算法，含协同过滤与深度学习 |
| G5 | 提供 Web 端可视化交互平台 | 支持查询、分析、预测、推荐、管理五大功能 |
| G6 | 实现 Java 后端与 Python 算法引擎跨语言调用 | 接口响应 P95 < 10s（模型已预热） |

### 2.2 关键数据画像结论

**（1）元数据字段结构（26 字段）**

- 标识类：`anime_id`、`name`、`english_name`、`japanese_name`
- 评分类：`score`、`scored_by`、`rank`
- 热度类：`members`、`favorites`、`popularity`
- 内容类：`genres`、`primary_genre`、`type`、`episodes`、`duration`、`duration_minutes`
- 时间类：`aired`、`start_date`、`year`、`premiered`
- 制作类：`studios`、`producers`、`licensors`、`source`
- 分级类：`rating`、`status`

**（2）数据完整性**

| 字段 | 缺失量 | 缺失率 | 处理策略 |
| --- | --- | --- | --- |
| `primary_genre` | 554 | 11.1% | 由 `genres` 首项回填，仍缺失记 `Unknown` |
| `start_date` / `year` | 1 | 0.02% | 众数回填 |
| 其余 24 字段 | 0 | 0% | 无需处理 |

> 结论：数据集**整体质量高**，缺失集中在主类型字段，可通过派生规则修复。

**（3）数值分布特征（关键发现）**

| 指标 | 均值 | 中位数 | 标准差 | 最大值 | 分布特征 |
| --- | --- | --- | --- | --- | --- |
| `score` 评分 | 6.37 | 6.36 | 0.93 | 9.07 | 近似正态，适合回归 |
| `members` 成员数 | 60,444 | 4,858 | 195,421 | 2,882,333 | **极强右偏长尾** |
| `favorites` 收藏数 | 707 | 7 | 4,940 | 182,964 | **极强右偏长尾** |
| `episodes` 集数 | 10.6 | 2 | 32.5 | 1,565 | 右偏长尾 |
| `duration_minutes` | 24.6 | 23.0 | 25.3 | 168.0 | 双峰（TV 24min / 剧场版 90min+） |
| `popularity` 人气 | 8,269 | 8,106 | 4,946 | 19,191 | 近似均匀 |
| `year` 年份 | 2007 | 2011 | 14.5 | 2023 | 随时间增长 |

> **关键结论 1**：热度类指标（`members`/`favorites`）呈**幂律长尾分布**，
> 直接回归效果受限，**必须做对数变换（log1p）** 后建模。
>
> **关键结论 2**：`members` 与 `favorites`、`scored_by` 存在强相关，
> 存在**特征泄漏风险**，热度预测的特征选择需谨慎（避免使用同源指标作为特征）。

**（4）类别分布**

- 动漫类型（6 类）：TV 1,429 / OVA 1,046 / Movie 788 / Special 650 / ONA 614 / Music 473
- 主类型 Top5：Action 1,293 / Comedy 1,068 / Adventure 401 / Hentai 369 / Drama 304
- 原作来源 Top5：Original 1,455 / Manga 1,271 / Unknown 593 / Visual novel 354 / Game 296
- 分级 Top3：PG-13 2,238 / G(全年龄) 1,221 / Rx 461
- 制作公司：UNKNOWN 1,140 / Toei Animation 227 / Sunrise 158 / J.C.Staff 120 / Madhouse 108

> **结论**：类别字段存在 `Unknown/UNKNOWN` 语义缺失值，需统一为缺失处理；
> 制作公司头部集中度低（长尾），不适合直接作为高基数类别特征。

**（5）用户行为数据画像**

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| 评分数 | 100,000 | — |
| 用户数 | 2,000 | — |
| 动漫数 | 4,695 | — |
| 评分区间 | 0.5 ~ 5.0 | 步长 0.5，5 级评分制 |
| 平均评分 | 3.739 | 偏正面评价 |
| **矩阵稀疏度** | **98.935%** | 用户-物品矩阵极度稀疏 |
| 训练/测试划分 | 80,000 / 20,000 | 8:2 |

> **关键结论 3**：评分矩阵稀疏度高达 98.9%，
> **基于内存的协同过滤（KNN）覆盖率受限**，需引入
> **矩阵分解（SVD）与深度学习（NCF）** 以缓解稀疏性问题。

| 基本流程 | 1. 用户进入「热度预测」页<br>2. 选择预测模型（6 种可选）<br>3. 填写集数、成员数、单集时长、语言、类型<br>4. 点击「开始预测」<br>5. 后端调用 Python 引擎推理<br>6. 返回预测热度值 + 模型指标（R²/RMSE/MAE）+ 热度等级 |
